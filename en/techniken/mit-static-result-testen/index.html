    Test with Static Result without changing data

    Quiz question

    What does Static Result do to an action?

    Solution

    1. A) It runs, but its output is not savedWrong. With Static Result the action does not run at all. That is exactly why it changes no data.
    2. B) It only runs when you start the flow manuallyWrong. Static Result does not depend on how the flow starts. It applies to every run as long as it is turned on.
    3. C) It returns a fixed output without runningCorrect. The action counts as successful and passes on the predefined result without actually running.

    What it is about

    Some actions you don't want to actually run while testing: they send emails, change records or take a long time. With Static Result you give an action a fixed result. In the designer you turn on Enable Static Result in the Testing section of the action and define which output it should return. On the next run the action counts as successful without being executed. The following steps continue with your predefined output. That way you test the logic after it calmly and with different cases, without touching real data. Before the flow goes into production, you turn the static result off again.

    When to use it, when not

    Use it

    For actions that send emails, change data or take long, while you test the steps after them.

    Better not

    In production. If Static Result stays on, the flow never actually runs the action.

    Most common mistake

    Leaving Static Result on after testing. The flow reports success although the action never ran.
