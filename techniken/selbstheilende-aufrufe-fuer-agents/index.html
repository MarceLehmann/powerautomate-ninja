    Selbstheilende Aufrufe für Agents

    Quizfrage

    Warum kann ein Agent Fehler eines direkt gebundenen Connectors nicht selbst korrigieren?

    Auflösung

    1. A) Agents dürfen in Copilot Studio keine Connectoren nutzenFalsch. Connectoren lassen sich direkt als Werkzeug binden. Das Problem ist, was bei einem Fehlerstatus passiert.
    2. B) Connectoren melden Fehler nur per Mail an den BesitzerFalsch. Der Aufruf endet als fehlgeschlagener Tool-Aufruf mit einem Fehlercode wie HTTP404NotFound, nicht mit einer Mail.
    3. C) Der Aufruf scheitert, bevor die Meldung der API ankommtRichtig. Ein Status ausserhalb von 2xx beendet den Tool-Aufruf mit einem Fehlercode. Erst ein Flow, der immer lesbares JSON zurückgibt, macht die Meldung für den Agent sichtbar.

    Worum es geht

    Bindest du einen Connector direkt als Werkzeug an einen Copilot-Studio-Agent, endet jeder Status ausserhalb von 2xx als Fehler, etwa HTTP404NotFound oder HTTP422UnprocessableEntity. Die Erklärung der API erreicht den Agent nicht, und er kann sich nicht korrigieren. Die Lösung ist ein Flow dazwischen. Der Aufruf liegt in einem Scope, die nächste Aktion läuft nach «is successful», «has failed» und «has timed out». Am Ende gibt «Respond to the agent» immer dieselbe Form zurück: ok, status, error und data. Den Status liest coalesce() aus, ohne Antwort wird er 0. So sieht der Agent die Meldung, passt Pfad oder Body an und versucht es erneut. Begrenze die Versuche in den Anweisungen, zum Beispiel auf drei. Korrekturen, die immer gelten, schreibst du in die Beschreibung des Werkzeugs.

    Der Ausdruck aus dem Tipp

    coalesce(outputs('HTTP')?['statusCode'], 0)

    Wann einsetzen, wann nicht

    Einsetzen

    Wenn ein Agent eine API über einen Connector oder die Aktion HTTP aufruft und falsche Pfade oder Bodys vorkommen können.

    Lieber nicht

    Wenn der Aufruf regelmässig länger als 100 Sekunden braucht. Dann endet der Flow mit FlowActionTimedOut, bevor eine Antwort ankommt.

    Häufigster Fehler

    Die Versuche nicht begrenzen. Dann wiederholt der Agent den Aufruf immer wieder und verbraucht Tokens, statt den Fehler zu erklären.

    Lizenz

    Premium Für Premium-Connectoren oder -Funktionen brauchst du passende Nutzungsrechte, etwa aus Power Automate Premium, Process, Power Apps oder Dynamics 365. Prüfe vorhandene Lizenzen im Lizenz-Check. Beleg bei Microsoft Learn: List of all Premium tier connectors, FAQ for agent flows. Für deinen ganzen Flow: Lizenz-Check.
