    Des appels auto-correcteurs pour les agents

    Question de quiz

    Pourquoi un agent ne peut-il pas corriger lui-même les erreurs d'un connecteur lié directement ?

    Solution

    1. A) Les agents n'ont pas le droit d'utiliser des connecteurs dans Copilot StudioFaux. Les connecteurs peuvent être liés directement comme outil. Le problème, c'est ce qui se passe avec un statut d'erreur.
    2. B) Les connecteurs ne signalent les erreurs que par e-mail au propriétaireFaux. L'appel se termine comme un appel d'outil échoué avec un code d'erreur comme HTTP404NotFound, pas par un e-mail.
    3. C) L'appel échoue avant que le message de l'API n'arriveExact. Un statut hors 2xx termine l'appel d'outil avec un code d'erreur. Seul un flux qui renvoie toujours un JSON lisible rend le message visible pour l'agent.

    De quoi s'agit-il

    Si tu lies un connecteur directement comme outil à un agent Copilot Studio, chaque statut hors 2xx se termine en erreur, par exemple HTTP404NotFound ou HTTP422UnprocessableEntity. L'explication de l'API n'atteint pas l'agent, et il ne peut pas se corriger. La solution est un flux intermédiaire. L'appel se trouve dans une Étendue, et l'action suivante s'exécute après « a réussi », « a échoué » et « a expiré ». À la fin, « Répondre à l'agent » renvoie toujours la même forme : ok, status, error et data. coalesce() lit le statut, et sans réponse il devient 0. L'agent voit ainsi le message, adapte le chemin ou le corps et réessaie. Limite les tentatives dans les instructions, par exemple à trois. Les corrections qui valent toujours, tu les écris dans la description de l'outil.

    L'expression de l'astuce

    coalesce(outputs('HTTP')?['statusCode'], 0)

    Quand l'utiliser, quand l'éviter

    À utiliser

    Quand un agent appelle une API via un connecteur ou l'action HTTP et que des chemins ou des corps erronés peuvent survenir.

    Plutôt pas

    Quand l'appel dure régulièrement plus de 100 secondes. Le flux se termine alors avec FlowActionTimedOut avant qu'une réponse n'arrive.

    Erreur la plus fréquente

    Ne pas limiter les tentatives. L'agent répète alors l'appel sans fin et consomme des jetons au lieu d'expliquer l'erreur.
