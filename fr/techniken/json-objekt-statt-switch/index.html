    Un objet JSON plutôt qu'un Commutateur

    Question de quiz

    À quoi servent les deux ? dans outputs('Compose')?[variables('InputValue')]?['Title'] ?

    Solution

    1. A) Elles évitent une erreur en cas de clé inconnueExact. Si la clé ou le champ manque, l'expression renvoie null au lieu d'une erreur.
    2. B) Elles marquent les valeurs comme entrées facultativesFaux. Le point d'interrogation n'a rien à voir avec des entrées. Il protège seulement l'accès à une propriété.
    3. C) Elles convertissent automatiquement le résultat en texteFaux. Le point d'interrogation ne change pas le type. Pour du texte, il te faut string().

    De quoi s'agit-il

    Un Commutateur avec une douzaine de cas, ou des conditions sur trois niveaux, est difficile à lire, et pour chaque nouveau cas tu modifies la structure du flux. Souvent, il s'agit seulement de retrouver une valeur à partir d'une clé. Pour cela, tu ranges dans une action Composer un objet JSON avec tous les cas, par exemple A, B et C avec un titre et une description chacun. Tu récupères la valeur voulue avec une expression comme outputs('Compose')?[variables('InputValue')]?['Title']. Les deux points d'interrogation évitent une erreur quand la clé ou le champ manque. Avec coalesce(), tu définis une valeur de remplacement pour les clés inconnues. Tu ajoutes les nouveaux cas dans le JSON, le flux lui-même reste identique.

    L'expression de l'astuce

    outputs('Compose')?[variables('InputValue')]?['Title']

    Quand l'utiliser, quand l'éviter

    À utiliser

    Quand un Commutateur ne fait que chercher des valeurs : statuts, textes, adresses ou réglages par environnement.

    Plutôt pas

    Quand les cas doivent déclencher des actions différentes. Le Commutateur reste alors le bon outil.

    Erreur la plus fréquente

    Ne pas gérer les clés inconnues. Sans coalesce(), null continue son chemin et ne se remarque que bien plus tard.
