    Rinominare un file SharePoint tramite REST

    Domanda del quiz

    Perché rinomini con FileLeafRef invece di copiare?

    Soluzione

    1. A) Copiare nelle librerie non è mai possibileSbagliato. Copiare è possibile, ma di solito crea un nuovo elemento. Cronologia delle versioni e metadati possono andare persi.
    2. B) FileLeafRef cambia subito anche l'estensione del fileSbagliato. Nell'esempio del tip la modifica dell'estensione tramite FileLeafRef non ha avuto effetto. Per questo usa MoveTo.
    3. C) ID, versioni e metadati vengono mantenutiEsatto. MERGE su FileLeafRef cambia solo il nome. L'elemento resta lo stesso.

    Di cosa si tratta

    Il connettore SharePoint non ha un'azione per rinominare. Copiare ed eliminare di solito crea un nuovo file con un nuovo ID. Cronologia delle versioni e metadati possono andare persi. Più pulita è una singola chiamata con «Invia una richiesta HTTP a SharePoint». Invii un POST all'elemento dell'elenco del file e con le intestazioni IF-MATCH: * e X-HTTP-Method: MERGE lo trasformi in una modifica. Nel body c'è solo il campo FileLeafRef con il nuovo nome file, estensione compresa. Con le intestazioni odata=nometadata non serve la voce __metadata. La risposta 204 significa successo. ID, versioni, autorizzazioni e metadati restano. Nell'esempio del tip la modifica dell'estensione del file non ha avuto effetto. Per questo usi MoveTo.

    L'espressione dal tip

    X-HTTP-Method: MERGE

    Quando usarla, quando no

    Usala

    Per convenzioni di denominazione, numeri di riferimento nel nome del file o correzioni a file caricati.

    Meglio di no

    Quando devono cambiare l'estensione o la cartella. Per questo la chiamata giusta è MoveTo.

    Errore più frequente

    Omettere l'estensione durante la ridenominazione. Mantienila nel nuovo nome file e controlla il nome dopo la chiamata.
