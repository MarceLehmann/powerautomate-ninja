    Un flusso come router per gli strumenti dell'agente

    Domanda del quiz

    Cosa controlla il parametro action nel flusso router?

    Soluzione

    1. A) Se il flusso richiede una licenza PremiumSbagliato. action sceglie solo l'operazione. La licenza dipende da come il flusso viene fatturato, come flusso dell'agente o come flusso cloud.
    2. B) La lingua in cui risponde l'agenteSbagliato. action non c'entra con la lingua dell'agente. Il parametro sceglie l'operazione nel flusso.
    3. C) Lo switch verso get, create o updateEsatto. Lo Switch su action porta nel ramo get, create o update. Il parametro input porta un filtro OData o un body JSON.

    Di cosa si tratta

    Un agente di Copilot Studio deve leggere, creare e modificare dati. Per questo non serve un server MCP con trigger HTTP e connettore personalizzato. Basta un flusso con il trigger «Quando un agente chiama il flusso», che dai all'agente come strumento. Il trigger riceve due input: action con i valori get, create o update e input come testo generico. Uno Switch su action porta nel ramo giusto. Con get, input è un filtro OData e va direttamente nella query di filtro. Con create e update, input è un body JSON che Analizza JSON scompone. Ogni ramo imposta la variabile result, che crei prima dello Switch. Alla fine «Rispondi all'agente» restituisce un JSON fisso, entro 100 secondi e con risposta asincrona disattivata. Il valore di input lo leggi con triggerBody()?['text'].

    L'espressione dal tip

    triggerBody()?['text']

    Quando usarla, quando no

    Usala

    Quando un agente interno ha bisogno di più operazioni collegate sulla stessa tabella o lo stesso elenco e vuoi mantenere un solo flusso.

    Meglio di no

    Quando l'agente confonde spesso le operazioni. Flussi separati con una descrizione propria li sceglie spesso in modo più affidabile.

    Errore più frequente

    Nel ramo update far riferimento ad Analizza JSON del ramo create. Quel ramo non è stato eseguito e l'espressione fallisce.
